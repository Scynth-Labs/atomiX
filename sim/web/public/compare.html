What is actually being compared

The three profiles are identical apart from core: the same SoC, interconnect, cache, memory, UART, and payload. So the spread between them is attributable to the core rather than merely correlated with it — which is the only way a number like this is worth quoting.

The payload is sw/baremetal/examples/cpu_perf.c, the same binary in every machine. It reads mcycle and minstret around five workloads, so its figures are retired instructions over elapsed cycles — a property of the machine, not of how the workload was compiled. It also prints a checksum, and the checksums must match: three cores that disagree about RV32IM would be a correctness bug, not a performance result.

make -C sim/web compare runs this same set headlessly under Node and fails if any machine misreports which selection it is, if the checksums differ, or if two machines return the same cycle count — the last being what a page showing one machine three times would look like.
